# COVID-19 Tracker

COVID-19 Tracker — веб-приложение для просмотра мировой статистики распространения COVID-19 и анализа показателей отдельных стран. Панель мониторинга отображает число зарегистрированных случаев и смертей, исторические графики, интерактивную карту мира, сравнение стран, каталог стран с подробной статистикой по каждому государству, показатели тестирования, персональный список избранного и экспорт статистики в CSV.

## Использование

После запуска через Docker Compose откройте [http://localhost:8080](http://localhost:8080). При локальном запуске через npm интерфейс доступен на [http://localhost:3000](http://localhost:3000).

- **Dashboard** (`/`) — мировые показатели, исторический график случаев и смертей, интерактивная карта, рейтинг стран и таблица с последними доступными данными.
- **Countries** (`/countries`) — поиск по названию, выбор континента, сортировка, пагинация и экспорт текущей страницы таблицы в CSV.
- **World map** (`/map`) — карта мира с маркерами стран и территорий, переключением показателей заболеваемости и смертности, всплывающей статистикой и переходом на страницу страны.
- **Country details** (`/countries/:code`) — показатели выбранной страны, население, доступная статистика тестирования, исторический график, экспорт графика в CSV и дата отчёта.
- **Compare** (`/compare`) — сравнение от двух до четырёх стран по случаям и смертям, с общим диапазоном дат, выбором масштаба и семидневного среднего.
- **Favorites** (`/favorites`) — сохранённые страны и их последние доступные показатели.

На исторических графиках доступны периоды 7, 30, 90 дней и всё время наблюдений, переключение между случаями и смертями, новыми и суммарными значениями. Для новых случаев и смертей доступно семидневное скользящее среднее. При наличии сведений о населении можно просмотреть показатели на миллион жителей. Выбранные интервалы отсчитываются от даты последнего наблюдения в источнике.

Кнопка **Export current page CSV** в разделе Countries сохраняет только строки текущей страницы таблицы с учётом активных фильтров и сортировки. Кнопка **Download CSV** над историческим графиком сохраняет даты и значения выбранного ряда с учётом периода, показателя, сглаживания и масштаба. Экспорт выполняется в браузере без повторного запроса к серверу. Файлы кодируются в UTF-8; отсутствующие наблюдения сохраняются как пустые поля, а не нули. Кнопки экспорта недоступны до загрузки данных.

В разделе Compare можно выбрать от двух до четырёх стран, показатель (накопленные и новые случаи или смерти, семидневное среднее), масштаб и временной диапазон. График и таблица используют общие даты наблюдений; отсутствующие значения показываются как пропуски. Период 7/30/90 дней отсчитывается от последней общей даты наблюдения. Доступен также произвольный диапазон.

На карте доступны четыре показателя: подтверждённые случаи, зарегистрированные смерти, случаи на миллион и смерти на миллион жителей. Размер кругов зависит от выбранного показателя. Нажмите на круг, чтобы увидеть значения и дату статистики; ссылка во всплывающей карточке открывает страницу страны. Масштабируйте карту кнопками «+» и «−»; прокрутка колесом мыши не изменяет масштаб карты. Для отображения подложки необходимо сетевое соединение с OpenStreetMap. Маркеры размещены приблизительно в географических центрах государств.

На странице страны раздел **Testing statistics** показывает общее и новое число тестов, тесты на тысячу жителей и долю положительных тестов, когда соответствующие сведения опубликованы. Доля положительных тестов отображается в процентах, остальные относительные значения рассчитываются по населению. Если тестирование не отражено в источнике, отображается сообщение об отсутствии данных. Период отчётности по тестированию может отличаться от даты обновления статистики случаев и смертей.

В разделе Countries нажмите на название страны, чтобы открыть её подробную страницу. Звёздочка в таблице стран или в профиле добавляет страну в Favorites; повторное нажатие удаляет её из избранного. Выбранные страны сохраняются в `localStorage` браузера и доступны после перезагрузки страницы. Список индивидуален для браузера и не требует учётной записи. Статистика для сохранённых стран загружается из API при открытии страницы Favorites. При отсутствии связи с API приложение сообщает об ошибке и позволяет повторить запрос. Числовые значения и даты поступают с сервера; отсутствующие показатели обозначаются символом «—».

### Запуск через Docker Compose

Из корня репозитория выполните:

```bash
docker-compose up -d --build
```

Приложение будет доступно на `http://localhost:8080`. Nginx раздаёт статические файлы React и передаёт запросы `/api/` на NestJS во внутренней сети Docker.

Чтобы проверить доступность API, выполните:

```bash
curl http://localhost:8080/api/v1/health
```

Для просмотра журналов и остановки контейнеров:

```bash
docker-compose logs -f
docker-compose down
```

Статистика сохраняется в Docker volume `statistics_data` и остаётся доступной после повторного запуска контейнеров. Команда `docker-compose down -v` удаляет этот volume вместе с сохранённой статистикой.

### API статистики

NestJS получает данные из [Our World in Data](https://github.com/owid/covid-19-data) и возвращает их через REST API. Синхронизация запускается при старте сервера и затем выполняется по заданному интервалу (по умолчанию каждые 60 минут). Загруженные данные проходят проверку структуры и сохраняются в JSON-файл атомарной записью.

Исторические ряды загружаются из полного CSV-файла Our World in Data при первом запросе к API истории. CSV читается потоком, а обработанный набор сохраняется на диск в сжатом формате (`.json.gz`). При повторных запросах используются сохранённые наблюдения. Обновление исторических рядов выполняется по запросу после истечения 24 часов; предыдущие данные доступны при ошибке обновления. Первая загрузка исторических рядов требует получения полного CSV-файла и может занять больше времени, чем обычный запрос сводки.

При перезапуске сервера последняя успешно сохранённая статистика загружается с диска. Если внешний источник недоступен, приложение продолжает отдавать сохранённые данные и повторяет запрос позже. Когда корректных данных нет ни в памяти, ни в сохранённом файле, API возвращает HTTP `503`. Одновременные запросы на обновление объединяются в одну операцию. Если статистика успешно загружена, но файл кэша временно недоступен для записи, обновлённые наблюдения остаются доступны из оперативной памяти. При следующем перезапуске используется последний сохранённый снимок.

| Метод | URL | Описание |
|---|---|---|
| GET | `/api/v1/health` | Проверка доступности сервера |
| GET | `/api/v1/summary` | Мировые показатели |
| GET | `/api/v1/countries` | Страны с фильтрацией и пагинацией |
| GET | `/api/v1/countries/:code` | Показатели страны по ISO-коду |
| GET | `/api/v1/countries/:code/history` | История статистики страны |
| GET | `/api/v1/summary/history` | История мировой статистики |
| GET | `/api/v1/map` | Показатели всех стран для интерактивной карты |
| GET | `/api/v1/compare` | Сравнение исторической статистики стран |
| GET | `/api/v1/meta` | Источник и дата данных |
| GET | `/api/v1/sync/status` | Состояние синхронизации |

Ошибки API возвращаются в едином JSON-формате: `statusCode`, `message`, `error`, `timestamp`, `path`. Некорректные параметры запроса дают `400`, отсутствие страны — `404`, недоступность статистики — `503`, необработанная ошибка — `500`. Внутренние сообщения исключений и stack trace не включаются в ответы с кодом `500`.

Браузер показывает понятные сообщения при ошибке сети, неуспешном HTTP-ответе, повреждённом JSON и превышении времени ожидания. Повторный запрос запускается кнопкой **Try again**; отменённые при переходе между страницами запросы не отображаются как ошибки. Для исторических данных и сравнения используется увеличенное время ожидания, учитывающее загрузку полного CSV-файла.


Маршрут `/api/v1/countries/:code` также возвращает необязательные поля тестирования: `totalTests`, `newTests`, `testsPerThousand` и `positiveRate`. Поле `positiveRate` содержит долю от 0 до 1, а браузер отображает её в процентах. Отсутствующие значения передаются как `null`; ранее сохранённые снимки могут не содержать этих полей до очередного обновления источника.

Маршрут `/api/v1/map` возвращает массив `items` со статистикой стран без пагинации, дату мировой сводки `date` и источник `source`. Клиент сопоставляет ISO-коды с локальным справочником географических координат и пропускает страны без координат или выбранного показателя.

Параметры `/api/v1/countries`:

- `search` — часть названия страны.
- `continent` — континент.
- `sortBy` — `name`, `totalCases`, `totalDeaths`, `newCases`, `newDeaths`, `casesPerMillion`, `deathsPerMillion`.
- `order` — `asc` или `desc`.
- `page` — номер страницы, начиная с 1.
- `limit` — размер страницы от 1 до 100.

Параметры `/api/v1/compare`:

- `codes` — от двух до четырёх различных ISO-кодов стран через запятую (обязательный параметр).
- `metric` — `totalCases`, `newCases`, `newCasesAverage`, `totalDeaths`, `newDeaths`, `newDeathsAverage` (по умолчанию `totalCases`).
- `scale` — `absolute` или `perMillion` (по умолчанию `absolute`).
- `period` — `7d`, `30d`, `90d`, `all` (по умолчанию на странице `30d`).
- `from`, `to` — даты `YYYY-MM-DD` для произвольного диапазона, несовместимы с `period`.

Ответ содержит общий массив `dates` и `countries`: для каждой страны возвращаются код, название, население, значения `values`, последнее доступное значение `lastValue` и его дата `lastValueDate`. Значения выровнены по датам, отсутствие наблюдений и населения передаётся как `null`. Для сравнения используется пересечение периодов отчётности выбранных стран.

Параметры маршрутов истории:

- `period` — `7d`, `30d`, `90d` или `all` (по умолчанию `all`).
- `from` и `to` — даты `YYYY-MM-DD` для произвольного периода. Эти параметры нельзя передавать вместе с `period`.

Ответ содержит `code`, `from`, `to`, `lastObservation`, `fetchedAt`, `source` и массив `points`. Каждая запись содержит дату, накопленные и новые случаи и смерти, а также `newCasesAverage` и `newDeathsAverage`. При отсутствии полного семидневного ряда среднее равно `null`; пропущенные наблюдения не превращаются в нули.

Примеры запросов:

```bash
curl http://localhost:3001/api/v1/health
curl http://localhost:3001/api/v1/summary
curl http://localhost:3001/api/v1/map
curl 'http://localhost:3001/api/v1/compare?codes=USA,ITA&metric=newCases&scale=perMillion&period=30d'
curl 'http://localhost:3001/api/v1/countries?search=pol&limit=10'
curl http://localhost:3001/api/v1/countries/POL
curl 'http://localhost:3001/api/v1/countries/POL/history?period=30d'
curl 'http://localhost:3001/api/v1/summary/history?period=90d'
curl http://localhost:3001/api/v1/sync/status
```

Поле `date` отражает дату статистического наблюдения. Время `fetchedAt` относится к загрузке данных на сервер и не заменяет дату публикации статистики. Данные могут пересматриваться их поставщиком.

Маршрут `/api/v1/sync/status` возвращает `state` (`synchronizing`, `ready`, `stale` или `unavailable`), `hasData`, `fetchedAt`, `dataDate`, `lastAttemptAt` и `lastSuccessAt`. Состояние `stale` означает, что последнее обновление завершилось ошибкой, но доступен ранее сохранённый набор данных.

## Разработка

### Требования

Для локального запуска:

- Node.js 14.x LTS.
- npm 6.x.
- Доступ к npm registry для установки зависимостей.
- Доступ к источникам CSV для загрузки сводной и исторической статистики.

Для отображения подложки карты нужен доступ к OpenStreetMap Tile Server. Отсутствие доступа к подложке не влияет на загрузку статистики из API. При публичном развёртывании необходимо соблюдать [политику использования картографических тайлов OpenStreetMap](https://operations.osmfoundation.org/policies/tiles/).

Для контейнерного запуска:

- Docker Engine 19.03 или новее.
- Docker Compose 1.27 или новее.
- Доступ к Docker Hub и npm registry для сборки образов.
- Доступ к источникам CSV со стороны backend-контейнера.

### Установка зависимостей

Из корня репозитория выполните:

```bash
cd client
npm install
cd ../server
npm install
```

При необходимости создайте `server/.env` из `server/.env.example`. Переменные сервера:

| Переменная | Значение по умолчанию | Описание |
|---|---|---|
| `COVID_DATA_URL` | URL CSV Our World in Data | Источник статистики |
| `COVID_DATA_CACHE_FILE` | `data/owid-statistics.json` | Путь к сохранённой сводке относительно рабочей папки сервера |
| `COVID_HISTORY_URL` | URL полного CSV Our World in Data | Источник исторических наблюдений |
| `COVID_HISTORY_CACHE_FILE` | `data/owid-history.json.gz` | Сжатый кэш исторических наблюдений |
| `COVID_SYNC_INTERVAL_MINUTES` | `60` | Интервал обновления (1–1440 минут) |
| `COVID_SYNC_RETRY_MINUTES` | `5` | Повторная попытка после ошибки (1–1440 минут) |

Приложение не требует регистрации и отдельной базы данных. Для сохранения статистики серверу необходим доступ на запись в каталог, указанный в `COVID_DATA_CACHE_FILE`. Этот каталог не включается в Git.

### Запуск Development сервера

В первом терминале:

```bash
cd server
npm run start:dev
```

Во втором терминале:

```bash
cd client
npm start
```

Frontend доступен на `http://localhost:3000`, backend API — на `http://localhost:3001`. Настройка `proxy` в `client/package.json` перенаправляет запросы `/api/*` на backend. Чтобы открыть страницу страны по прямой ссылке, используйте маршрут вида `http://localhost:3000/countries/POL`.

### Создание билда

Сборка backend:

```bash
cd server
npm run build
npm start
```

Сборка frontend:

```bash
cd client
npm run build
```

Статические файлы приложения будут размещены в `client/build/`, серверный JavaScript — в `server/dist/`.

## Тестирование

Для unit- и HTTP-тестов сервера используются Jest и Supertest. Проверяются формат ошибок API, валидация запросов и работа приложения при сбое записи локального кэша.  Проверяются сравнение стран и выравнивание исторических рядов, API карты, парсинг CSV и показателей тестирования, синхронизация, семидневные средние, выбор временных периодов, повторное использование сохранённой статистики, запись снимка на диск и работа REST API:

```bash
cd server
npm test
npm run test:e2e
```

Для тестирования React-компонентов, графиков, карты, страницы сравнения, статистики тестирования, избранного и его сохранения в `localStorage`, экспорта CSV, переключения показателей, страниц, форматирования данных, сетевых ошибок и резервного экрана при сбое интерфейса используются Jest и React Testing Library:

```bash
cd client
npm test
```

## Deploy и CI/CD

### Docker

Для сборки и запуска приложения используйте команды из раздела [Запуск через Docker Compose](#запуск-через-docker-compose).

Сервис `web` собирает production-версию React и обслуживает её через Nginx. Сервис `api` запускает NestJS в отдельном контейнере, а папка `/app/data` подключается к именованному Docker volume. Прямое подключение к порту API снаружи контейнерной сети не требуется.

Порт интерфейса задаётся в `docker-compose.yml` (`8080:80`). При размещении приложения на сервере настройте публичный адрес, HTTPS и обратный прокси согласно параметрам окружения.

Переменные `COVID_DATA_CACHE_FILE`, `COVID_HISTORY_CACHE_FILE`, `COVID_SYNC_INTERVAL_MINUTES` и `COVID_SYNC_RETRY_MINUTES` определяются в `docker-compose.yml`. Статистика загружается сервером при старте и обновляется по заданному расписанию.

### Continuous Integration

Конфигурация GitHub Actions находится в `.github/workflows/ci.yml` и выполняется при `push` и `pull_request`.

Пайплайн содержит три задания:

1. **client:** установка зависимостей, тесты React и production-сборка.
2. **server:** установка зависимостей, unit- и HTTP-тесты NestJS, сборка API.
3. **docker:** сборка Docker-образов frontend и backend после успешных проверок кода.

Проверки запускаются автоматически после отправки коммитов в GitHub или открытия pull request. Результаты доступны в разделе **Actions** репозитория.

Для локального выполнения соответствующих проверок:

```bash
cd client
npm install
npm test
npm run build

cd ../server
npm install
npm test
npm run test:e2e
npm run build
```

Публикация Docker-образов во внешний registry и автоматический deploy на сервер не настроены: для этого необходимы адрес окружения, доступы и параметры инфраструктуры.
